# The MCP server is a read-only stdio client of `/api/v1`

A developer in an editor should be able to ask the dashboard which CVEs affect the repo they are in. We ship that as a separate package in `mcp/` that speaks MCP over stdio and calls `/api/v1` with a read token (ADR 0002). It imports nothing from `src/`, so the REST API stays the single contract and the layering rules hold. v1 answers only questions about data the dashboard already tracks: project status for the current git remote, vulnerability lists and explanations, who uses a package, and later ranked upgrades.

Free text from OSV advisories and SBOMs reaches an agent's context, so the server truncates it and returns it in a field marked untrusted, never inside tool descriptions or summaries. Rejected: a remote HTTP MCP endpoint inside the Next.js app (a new auth surface to defend; revisit in its own ADR), and `check_before_adding` / `diff_working_tree` in v1. A package or lockfile the dashboard has never seen has no OSV data, and only the worker makes external calls, so answering means queueing a scan through Postgres: a write path, an authorising token and an ephemeral SBOM that must never become `latest_sbom_id`. That belongs with D-001 and its own decision (M-006).
